## 用户要求和工作假设

用户希望登录后的 Portal 借鉴 b.ai，特别是 Key 页：模型按全部、折扣等分组，每组展示价格；配置使用浮动窗口，支持模型搜索；页面末尾提供 curl、Python、Node.js、Shell 示例。

用户已明确：便宜 10% 表示按标准价的 90% 计费。

本轮采用的工作假设（尚非用户确认）：折扣组是筛选器，同一模型在所有组中价格一致；指定模型模式可跨组勾选。没有引入按 Key 选择不同费率或不同上游质量的计费组。未来若用户选择后一种业务含义，需要另行设计权限、价格快照和组路由，不能把筛选标签当成完成该能力。

## 用户界面

- 创建区与配置弹窗都有模型分组、名称搜索、已选数量，以及输入/输出/缓存读/缓存写四列。单位统一为 credits / 100 万 tokens。
- 默认全部可用模型；指定模型模式跨组保留勾选；禁止调用模式独立保留。分组和搜索只是筛选，不改变 Key 权限。
- 全部组包含折扣模型。常见便宜 10% / 20% 组以及已配置的其他比例会显示数量，空组显示没有匹配结果。旧配置中已下架但已选的模型保留，并标记当前未上架、价格未公布。
- Key 配置采用原生 `dialog.showModal()`，背景不可操作，使用浏览器的焦点约束；有明确标题，Esc 和关闭按钮可退出，返回打开前焦点。保存期间不能关闭或修改字段，失败保留内容；成功后显示反馈。
- 价格接口失败时清除过期的价格展示，保留选择并显示错误，不将未公布的价格显示为免费。
- 页面底部有四种语言示例，使用已配置 API Base，保留部署前缀并只追加一个 `/v1`，缺失配置明确使用占位符。示例不自动填入真实 Key；执行前由用户设置本机环境变量，显示按实际用量收费提示。
- Shell 是带隐藏密钥输入的 Bash 完整脚本，curl 是单次请求；Python 使用标准库，Node.js 使用内置 fetch。示例不会在网页自动执行。

## 模型价格数据

`PointPrice` 新增：

- `discount_percent`：0–99 的整数，0 为原价；10 表示便宜 10%。
- `standard_price`：折扣模型的四项标准价。无优惠时省略。
- 现有 `input_per_million` 等四个字段始终是实际扣费价，供列表展示和请求价格快照读取。

管理员在价格编辑器填写标准价与优惠比例，服务端使用有理数计算有效费率，统一保留六位小数。禁止正价格折后低于支持精度而变成零。缓存标准价为零时仍是零。

数据库只追加 `discount_percent` 和 `standard_price` 两列，旧模型默认为 0% 优惠，保留原价格。未向任何生产模型自动设置优惠。报价、版本号与审计记录在同一事务更新，保留并发修改冲突检查。

`GET /api-key-models` 保留原有 `models` 字段，增加同范围 `prices` 和单位。只有已上架且符合账户模型策略的价格进入选择目录。最终 API 调用权限仍由原有账户与 Key 策略共同执行。

付费请求继续在入站时绑定有效价格和版本。后续改价不会追溯改变已经开始请求的费用。无优惠的旧价格写入格式仍可使用；优惠写入必须提供标准价，避免对折后价重复打折。

## 部署与验收边界

该改动包含数据库新增列，因此不能只替换静态文件就声称完成全功能部署。需要发布包含前后端的同一候选版本。回滚旧二进制不会删除新增列，但旧版管理员价格编辑器不了解优惠字段；如果已启用优惠，回滚后的调价必须先审查，避免标准价元数据与有效价格不同步。
